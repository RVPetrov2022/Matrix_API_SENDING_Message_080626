# Часть 1 🚀 Мониторинг 620 ИТП через корпоративный мессенджер Matrix Synapse на Debian 13

В этом видео подробно разбираем архитектуру, логику работы скриптов и особенности настройки сервера **Matrix Synapse** для системы автоматического сбора логов и диспетчеризации индивидуальных тепловых пунктов (**ИТП**) крупных жилых комплексов (**ЖК**).

Вся система развернута на базе **Debian 13**. Сервер **Matrix Synapse** работает в **Docker**, а база данных **PostgreSQL** для максимальной надежности и производительности вынесена за пределы контейнера на хостовую машину.

---

### 📌 СТРУКТУРА ДАННЫХ И МАРШРУТИЗАЦИЯ СИГНАЛОВ

В **Matrix** создано единое Пространство **«ПИК»**, объединяющее **103 комнаты** (по количеству ЖК). Для связки логов с мессенджером была сформирована итоговая таблица из **5 столбцов**:

1. Номер объекта ЖК
2. Номера ИТП (всего **620 ИТП**, опрашивается **520 серверов**)
3. Название ЖК
4. Адрес ИТП
5. ID комнаты в Matrix (**Room ID**)

---

### ⚙️ АЛГОРИТМ РАБОТЫ СИСТЕМЫ МОНИТОРИНГА

* **Чтение логов:** Скрипт последовательно сканирует **620 лог-файлов**, поступающих с серверов ИТП.
* **Маршрутизация:** При обнаружении новой записи скрипт определяет ID файла, сопоставляет его со справочной таблицей и мгновенно отправляет тревожное или информационное сообщение в строго определенную комнату конкретного ЖК.
* **Защита от спама и бана:** Реализована интеллектуальная защита токена. Если с ИТП начинает идти сплошной поток ошибок («заспамливание»), скрипт дозирует отправку, чтобы **Matrix-бот** не заблокировал сам себя.
* **Сторожевой таймер (Watchdog):** Работает глобальный контролирующий скрипт. Если в течение **15 минут** ни в один из 103 чатов не пришло ни одного сообщения (признак зависания опроса логов), скрипт-хранитель автоматически перезапускает основной поток. Если связь не восстановилась, повторные перезапуски идут с интервалом в **5 минут**.

### 🔧 ОПТИМИЗАЦИЯ СЕРВЕРА MATRIX SYNAPSE

По умолчанию **Matrix** жестко блокирует частые сообщения (**Rate Limiting**).
### 🔧 ОПТИМИЗАЦИЯ СЕРВЕРА MATRIX SYNAPSE (Продолжение)

Чтобы система выдерживала пиковые аварийные нагрузки сотен серверов, в конфигурационном файле `homeserver.yaml` были изменены лимиты защиты от спама. Теперь сервер стабильно переваривает до **1000 входящих сообщений в минуту** без задержек и отсечек.

---

### 🔄 АВТОМАТИЧЕСКАЯ СИНХРОНИЗАЦИЯ ОБЪЕКТОВ (CRUD)

Написан отдельный управляющий скрипт для динамического ведения базы объектов. Он сверяет текущий текстовый список ЖК с базой данных мессенджера:

* **Добавление:** Если в списке появляется новый ЖК — скрипт сам создает для него комнату в **Matrix** и добавляет её в Пространство **ПИК**.
* **Удаление:** Если ЖК удаляется из списка — скрипт автоматически очищает и удаляет устаревшую комнату из БД **Matrix**.
